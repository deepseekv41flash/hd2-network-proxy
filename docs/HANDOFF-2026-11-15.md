## 1. 这条路线的定位

| 能做 | 不能做 |
|---|---|
| 改**客户端收到的**战况/目录/改装数据（`Status` / `warinfo` / `Progression/*`） | 改服务端真实战况（上游数据不受影响，见 §6.1） |
| 造出星图上不存在的星球/战役/事件，并真的开一局 | 通过 `Mission/Session` 这类会话恢复端点（返回 `8012016`，见 §6.1） |
| 给账号"看起来拥有"物品（武器上架、配件解锁、外观、战备试用） | 真的写进账号（纯客户端可见，§6.1） |
| 借别的星球的生态/地形（`settingsHash`） | 绕过 EAC（EAC 只查游戏文件；代理不碰文件，所以**两件事互不相干**） |
| 与数据表路线**叠加**（表改数值、代理改上下文） | 把两者混为一谈（数据表线文档在另一个仓库，见 §3.3） |

**实现结构**（就三个动作）：

```
游戏 ──TLS──▶ 本机 100.67.169.17:443（war_proxy.py，自签 CA 签发叶子）
                │  ① 按路径命中钩子 → 解析 JSON → 增改字段 → 重发（去掉 Content-Length/Encoding）
                │  ② 别的一律原样转发（passthrough 模式下 ①②都跳过）
                └──TLS──▶ 官方 API（DNS-over-HTTPS 解析上游地址，见 doh_resolve）
```

### 4.4 `HD2_GWE_EXTRA` 全 schema

`_warinfo_apply_extra()`（warinfo 端点）：

```jsonc
{
  "settings_hash": {"<planetIndex>": <settingsHash>},   // 改已存在条目：借生态/地形
  "planet_infos": [{                                     // 追加 planetInfo：给"星图上不存在的星"补身份
    "index": 300, "settingsHash": 2995599666,
    "position": {"x": 0.30, "y": -0.55},
    "maxHealth": 1000000, "initialOwner": 2, "sector": 20,
    "waypoints": [180, 7]
  }]
}
```

`_gwe_apply_extra()`（Status 端点）：

| 键 | 结构 | 效果 |
|---|---|---|
| `campaigns` | `[{planet, id, type, count, race}]` | 追加战役（`type:0` 解放 / `type:4` 防守） |
| `attacks` | `[{source, target}]` | 追加攻击边（星图箭头） |
| `events` | `[{planet, eventType, race, health, maxHealth, startOffset, endOffset, campaignId?, id?}]` | 追加 `planetEvents`（自动配 `jointOperations`、自动算时间） |
| `globalEffects` | `{"<eventId>": [effectId...]}` | 全局效果挂到 `globalEvents[].effectIds` |
| `regions` | `[{planet, regionIndex, owner, maxHealth}]` | 补 `planetRegions` 缺失条目（只补不改） |
| `planet_nodes` | `[{index, owner, health, regenPerSecond, players, position}]` | 补 `planetStatus` 节点（星图要画点必须有） |
| `planet_effects` | `[{index, ids:[effectId...]}]` | **原始**追加 `planetActiveEffects`（绕开阵营过滤） |
| `owner` | `{"<index>": <1|2|3>}` | 覆盖 `planetStatus[].owner`（1 人类 / 2 虫族 / 3 机器人） |

> 所有键都做**去重**（已存在则跳过并记一行日志），因此重复执行安全。
> 一个可用的最小样本见 `run-planet300.ps1` 第 20–27 行（四件套造一颗可玩星）。

### 4.5 `config.json`

```json
{"host":"api.live.prod.thehelldiversgame.com", "listenIp":"100.67.169.17", "port":443,
 "crlPort":8080, "upstreamIp":"", "passthrough":false, "verbose":true,
 "allowDevFlags":false, "targets":[]}
```

- `listenIp` **不能是回环**（19411 起客户端在 TLS 握手前就断）；
- `upstreamIp` 空 = 用 DoH 解析上游；填 IP 可离线调试；
- `targets` 是变种选择（`panel.py` 写的就是它）；命令行实验一般留空，改用 `HD2_GWE_EXTRA`。

## 6. 边界、未测、已否证

### 6.1 三条硬边界（别再撞）

1. **服务端不落账**：300 号星那一轮，整条 op 链路服务器都接受（`Operation/Create`→`Mission/Start`→`Mission/end`
   结算 `campaignWon:true`），但**上游 Status 仍是 273 个节点、没有 300**。客户端侧是"真的"，战局侧是幻影。
2. **`Mission/Session` 有校验**：同一会话里 `GET /api/Mission/Session` 回
   `{"errorCode":8012016,"message":"PlanetIndex is invalid in this context"}` ⇒ 重连/会话恢复这类走它的路径会失败。
   校验点**存在但覆盖不全**，写进文档的措辞要按这个来，不要说成"服务器没有校验"。
3. **"服务器接受假 campaignId" 不构成缺校验的证据**：设计上作战就可脱离战役继续（`E8-REACHABILITY.md` §0.1）。
   这条曾被写错过，是**已更正的结论**。

另：阵营过滤（`resolve_plan` 里按 `owner` 拦）是**我们自己加的保护**，客户端并不拒绝跨阵营词条（§5 的 B 就是证据）。

### 6.2 未测清单（可以当 backlog）

| 编号 | 待测 | 判据 |
|---|---|---|
| B | `Mission/Session` 的边界：假星球 + 真 campaignId；真星球 + 注入 campaignId；断线重连 / 群组恢复 | 8012016 是否随组合变化 |
| C | 一次注入 ≥3 颗伪造星 | 星图/连线/性能是否异常 |
| D | 半套配置（四件套只给 2~3 件）分别表现 | 每缺一件的可见症状 |
| E | 防守注入 + 攻击箭头同时生效 | 箭头是否画出（§5 第一轮只加 `planetAttacks` 不画） |
| F | `planet_effects` 多条叠加 | 词条叠加/互相覆盖规则 |

### 6.3 已否证（不要重复走）

- 只在 Status 里追加 `planetStatus` 节点而不补 warinfo `planetInfo` ⇒ **星图不画**（四件套缺一不可）；
- 解放目标注入 `planetEvents` ⇒ 卡面出现 DEFEND 倒计时，自相矛盾；
- 只换 `+0x38` 粒子字段（数据表侧）⇒ 引擎不画；与本线无关但常被误当"代理能救"；
- 改写 L2 改装槽 ⇒ 只是把 L0 回显一遍，不是"独立入口"；
- 「服务器接受伪造字段 ⇒ 缺少校验」⇒ 措辞错误，见 §6.1.3。

## 7. Runbook

### 7.1 开工前（清场 → 重签 → 纯转发 → 验收）

```bash
cd /d/Downloads/variant_mod

# ① 清残留（不需要管理员）
powershell -File stop.ps1
netstat -ano | grep -E ":443 |:8080 "      # 必须为空

# ② 重签会话证书（≤2 天；会同时重写 anchor.cer/anchor.pem）
python tools/gen_session_certs.py --out-dir certs --mode ca --days 2 --force
certutil -user -addstore Root certs/anchor.cer   # CurrentUser，免 UAC

# ③ 起纯转发（先别开改写，确认链路通）
powershell -File run.ps1 -Passthrough
tail -5 logs/proxy.log                      # 看到 "proxy pid ..." 即成功

# ④ 验收（见 §7.4）
```

> `setup.ps1` 会改 hosts + 装证书（需要管理员）；**hosts 行现在已经在**，通常只需 ②。
> `run.ps1` 的前置检查：`certs/session.json` 存在、指纹被信任（机器或用户根）、hosts 有 `# variant-mod`、
> `logs/pids.json` 不存在。任一条不满足就打印 ERROR 并退出（退出码 1/2）。

### 7.2 起一次定向实验（用 `run-planet300.ps1` 当模板）

```powershell
$spec = @'
{"planet_effects":[{"index":76,"ids":[1243,1245]}]}
'@
$spec = ($spec -replace "`r?`n",' ').Trim()
$env:HD2_GWE_EXTRA = $spec
$env:HD2_GWE_DUMP  = 'D:\mod\out\gwe\<本次目录>'
$env:HD2_GWE_PATHS = '/api/WarSeason/801/Status,/api/WarSeason/801/warinfo,/api/Operation,/api/Mission'
$env:HD2_GWE_MAX   = '33554432'
& .\run.ps1
```

要点：**一次只开一组**（其余键不写、`targets` 留空、`runtime/*.json` 里无关的 `enabled` 关掉），
否则出问题无法归因。改完配置**重启游戏**（客户端只在启动/登录时拉战况），**不要重启代理**。

### 7.3 抓包

```powershell
$env:HD2_GWE_DUMP       = 'D:\mod\out\gwe\capture-<date>'
$env:HD2_GWE_PATHS      = 'api/'                                  # 全量响应
$env:HD2_GWE_REQ_PATHS  = 'api/Operation,api/lobby,api/Progression' # 请求体
```

抓完对账：`logs/proxy.log` 里出现过的路径 ↔ `out\gwe\<dir>\index.txt`，只有 REQ 没有 body 就是白名单漏了。

### 7.4 验收三连

```bash
# 代理在听 + 证书链可用
curl --noproxy '*' --resolve api.live.prod.thehelldiversgame.com:443:100.67.169.17 \
     --cacert certs/anchor.pem -sS \
     https://api.live.prod.thehelldiversgame.com/api/WarSeason/current/WarId
# 期望：{"id":801}

curl -sS http://127.0.0.1:8080/ca.crl -o /dev/null -w '%{http_code}\n'   # 期望 200

grep -c "STATUS " logs/proxy.log     # >0 说明游戏真的来拉过战况
```

> 命令行必须加 `--noproxy '*'`：本机有系统代理 `127.0.0.1:7897`，否则看到的是别人的证书链，
> 报 `untrusted root`。

### 7.5 收工

```bash
powershell -File stop.ps1          # 只停进程
powershell -File teardown.ps1      # 需要管理员：删信任证书 + 删 hosts 行（彻底还原）
```

日常实验**不必** teardown（hosts 留着更省事），但交公/换机前要 teardown。

### 7.6 故障对照表

| 症状 | 先查 |
|---|---|
| 游戏"与服务器通讯时出错"、日志里**没有任何** `/api/*` | 证书过期（看 `certs/session.json` 的 NotAfter）；443 是否在听 |
| 代理起了但游戏连不上 | `listenIp` 是不是回环地址；hosts 是否指向该 IP |
| 抓包目录只有 GWE 一种 | 没设 `HD2_GWE_PATHS` |
| 只有 `REQ` 没有响应体 | 白名单漏了该路径；或该请求走了 `304`（见下） |
| `WARN: Status 返回 304` | 条件头已剥离，下次应恢复；偶发一次可忽略 |
| `run.ps1` 退出码 2、提示 previous session pids | `logs/pids.json` 残留 → `stop.ps1` |
| Status 200 但没有 `REWRITE` | 游戏还没上报星球位置（正常时序）；或没选变种；看 `STATUS <n>B` 回执 |
| 星图错乱 / 崩溃 | `stop.ps1` → `run.ps1 -Passthrough` 回纯转发 |
| curl 报 `untrusted root` | 走了 7897 系统代理，加 `--noproxy '*'` |

## 8. 坑（本次会话新增的五条）

1. **两份 `war_proxy.py` 分叉**：工作副本 1846 行 vs 仓库 1665 行（缺 customize / `planet_effects`）。改代码前先确认改的是哪一份。
2. **pid 文件残留**：`pids.json`（13864）+ `proxy.pid`（12692）都不存在对应进程，但 `run.ps1` 见到 `pids.json` 直接拒启。先 `stop.ps1`。
3. **证书是硬期限**：`gen_session_certs.py` 上限 2 天；过期症状与"代理没启动"完全一样（443 直接停听，无任何错误日志）。
4. **gitbash 会把 `/api/` 转成 Windows 路径**：`HD2_GWE_PATHS="api/"`（不带前导斜杠）或 `MSYS_NO_PATHCONV=1`。否则过滤条件永不命中，抓包目录一片空白。
5. **中文双编码**：写中文进 `HD2_GWE_EXTRA` 会变乱码（如「鎺犻鍙樼」），变种匹配不上 —— spec 里只用 ASCII/数字。

（其余见 `OPS-PITFALLS.md`。）

## 9. 建议的下一个开发循环

面向"做成一个能发出去的 mod"，推荐顺序：

1. **先重建可复现的基线**（半天）：§7.1 起 passthrough，进游戏一次，确认 `STATUS` 回执 + 三条 curl + 抓一份上游 `Status` 存档。
2. **选一条能力做成品**（建议从 §5 里最稳的两条挑）：
   - **变种词条**（B）：单星球、单请求、UI 立即反馈，风险最低；
   - **休眠星可玩化**（E）：展示效果最强，但牵涉 4 个键 + 服务端边界（§6.1）。
3. **把"配置面"做成产品面**：现在的入口是环境变量 + `runtime/*.json`，成品需要一层"选星球/选效果 → 写配置 → 起代理"的 UX
   （`panel.py` 是现成的 Tk 骨架，`config.json.targets` 就是它的数据面）。
4. **收尾时把工作副本回灌仓库**：`variant_mod\tools\war_proxy.py` → `variant-net\tools\war_proxy.py`，
   并把新结论补进对应文档（研究结论留 `repo-datamined`，网络层留本仓库）。
5. **发布前的合规/安全自检**（沿用 README §安全设计）：证书名字受限、1–2 天有效期、单域名白名单、
   默认不落敏感日志、`teardown` 能一键还原。发布包里**不要**带 `runtime/*.json` 的实验残留和 `logs/`。
